🎯What problem this guide solves

If you use Claude Code to write books and Codex to generate images, you may have hit these walls:

  • 🚫 A message like: "Permission for this action was denied by the Claude Code auto mode classifier… [Safety Bypass Flag] The Codex call uses sandbox=danger-full-access…"
  • 💾 Codex generates images but cannot save them into your book folder
  • 📉 Claude Code silently falls back to HuggingFace image tools, which die with quota errors
  • 🔄 Weird sandbox errors on Windows that block files randomly
💡 How it works (explain-it-like-I'm-10 version)

Claude Code is the boss who writes the book. Codex is the artist who draws. But Codex runs inside a fenced play area (a sandbox). If the fence settings are wrong, the guard blocks everything. This guide sets the fence correctly — and hires a "delivery man" so no image ever gets stuck again.

1Fix Codex's settings file (the sandbox fix)

This is the fix for the "Safety Bypass Flag / danger-full-access" block. Instead of allowing the dangerous switch, we configure Codex to run safely with the right permissions: it may use the internet (needed for image generation) and write files inside your book folders.

1.1 — Open the settings file

Press Windows key + R, type this, and press Enter:

notepad %USERPROFILE%\.codex\config.toml

If Notepad asks "Do you want to create a new file?" → click Yes.

1.2 — Make the file look EXACTLY like this

Replace YourName/Books with your real book folder path:

sandbox_mode = "workspace-write"
approval_policy = "never"

[sandbox_workspace_write]
network_access = true
writable_roots = ["C:/Users/YourName/Books"]
LineWhat it does (plain English)
sandbox_mode = "workspace-write"Codex may write files, but only inside your allowed folders — safe.
approval_policy = "never"Codex won't freeze waiting for approvals nobody can answer when a robot runs it.
network_access = trueOpens the internet gate — required to generate images.
writable_roots = [...]The star of the show 🌟 — lists the folders Codex is allowed to save files into. Several folders? Separate with commas.
⚠️ Three golden rules for this file (people get burned here!)

1. No duplicates. Each setting must appear only once. If you paste the new settings below the old ones, the whole file breaks and Codex ignores everything.

2. Forward slashes only. Write C:/Users/... — never C:\Users\.... Backslashes break this file.

3. Save it. Ctrl + S, then close Notepad.

2Teach Claude Code the permanent IMAGE RULES

Claude Code has a memory file called CLAUDE.md. Rules written there apply to every future chat — permanently. This is how we stop the HuggingFace fallback, force the image style we want, auto-compress, auto-deliver, and auto-embed.

2.1 — Paste this entire block into Claude Code

Open Claude Code inside your book project folder and paste:

Set up my permanent book image pipeline.

PART 1 — Add these IMAGE RULES to my CLAUDE.md (permanent, all future sessions):

IMAGE RULES (permanent):
1. NEVER use HuggingFace image tools (Z-Image-Turbo, FLUX, or any huggingface MCP tool). Never fall back to HuggingFace — not even when quota has reset.
2. PRIMARY IMAGE ENGINE: Codex, always run from inside the current book project folder with --sandbox workspace-write. NEVER use danger-full-access.
3. If Codex cannot save the PNG into the project folder because of the sandbox: rescue the image — either extract it from the Codex session (codex-reply / base64) or copy it from the .codex/generated_images folder — and save it into the project folder yourself.
4. CODEX DELIVERY STEP (critical): Codex's built-in image generator saves images to C:\Users\MYUSERNAME\.codex\generated_images\<thread-id>\ and reports the full path in its reply (sometimes saying "read-only workspace prevented saving" — that is expected on this PC). After EVERY Codex image call: read the generated file path from Codex's reply, copy that PNG into the correct manuscript images/ folder, rename it to the requested name (e.g. IMG-37.png), verify the file exists and is bigger than 0 KB, delete the leftover original, then apply the compression rule. If the reply contains no file path, look for the newest file in .codex\generated_images\ (check subfolders, sort by date).
5. If image generation completely fails, STOP and show me the exact error. Do not silently switch tools.
6. STYLE: Every image must be PHOTOREALISTIC — like a real professional photograph (not cartoon, illustration, 3D render, or drawing) — in LANDSCAPE orientation with 16:9 aspect ratio.
7. COMPRESSION: After every image is saved, automatically compress it: resize to a maximum of 1600 pixels on the longest side, save as JPEG quality 85 (replacing the large PNG), target under 500 KB per image. Do this automatically without asking me.
8. PLACEMENT: After images are ready, embed each one into the book document exactly where it belongs — directly under the paragraph or section it illustrates — sized to fit the page width neatly, before the book is considered finished.

PART 2 — Verify the Codex config file at C:\Users\MYUSERNAME\.codex\config.toml contains: sandbox_mode "workspace-write", approval_policy "never", network_access true, and writable_roots including this project folder (or its parent). Fix it if anything is missing. Use forward slashes in paths.

PART 3 — TEST now: generate one test image with Codex: "photorealistic close-up of a doctor's hands holding a stethoscope over a medical chart, bright clinic lighting, sharp focus, 16:9 landscape". Deliver it with rule 4, compress it with rule 7, and show me the final file name, dimensions, and size.
✅ What each rule protects you from

Rule 1 kills the HuggingFace quota trap. Rule 2 keeps Codex safe (no danger-full-access, so no security-guard blocks). Rules 3–4 mean no image is ever lost even when the Windows sandbox acts up. Rule 5 stops silent tool-switching. Rules 6–8 guarantee photorealistic 16:9 images, small file sizes, and images placed exactly where they belong in the book.

3Restart and test

  1. Close Claude Code completely (all windows/terminals) and open it again in your book project folder — it must re-read the new settings.
  2. Ask: "Generate one test image with Codex, deliver it, compress it, and show me where it is."

✅ Success looks like:

  • No security-guard / permission-denied messages
  • No HuggingFace anywhere in the logs
  • A photorealistic, landscape 16:9 image sitting in your images/ folder
  • File size under 500 KB (compressed automatically)
  • Image embedded in the document exactly where it belongs
🔁 From now on, every session

Just say things like "Write Chapter 3 with images" — generation, delivery, compression and embedding all happen automatically.

4Monitor your Codex daily usage

Codex limits are set by your OpenAI plan (not by Claude Code). Limits work like a phone battery: they drain as Codex works and refill on a rolling ~5-hour window, plus a weekly cap.

  • 👀 Check your exact remaining usage: chatgpt.com/codex/settings/usage (the official Codex Usage Dashboard)
  • 🧾 OpenAI does not publish an official images-per-day number — watch your dashboard before and after a batch of ~10 images to learn your personal budget
  • 🔋 Practical planning: on a Plus plan, budget a few dozen images per day; a typical book (30–80 images) takes 1–2 days
💡 Three separate meters

Your Anthropic/Claude plan meter covers the writing 🧠. Your OpenAI/Codex meter covers the images 🎨. They don't share fuel — when one empties, the other keeps working.

🎁Optional — Free backup image engine (when Codex rests)

OPTIONAL This works and costs nothing, but be aware: the free tier currently serves a fast, softer-quality model. Use it only as an emergency backup or for drafts — Codex remains your quality king. 👑

Backup option A — Pollinations.ai (automatic, free)

  1. Go to enter.pollinations.ai → free signup (no card) → create a secret API key (starts with sk_) → copy it immediately (shown only once!).
  2. Paste this into Claude Code:
Add Pollinations as my BACKUP image engine:

1. Add this line to .env:  POLLINATIONS_TOKEN=sk_paste_your_key_here
2. Add a backup engine to my image script that:
   - URL-encodes the prompt and downloads from the CLASSIC FREE endpoint only:
     https://image.pollinations.ai/prompt/{prompt}?width=1024&height=576&nologo=true&seed={random}&key={POLLINATIONS_TOKEN}
   - NEVER uses gen.pollinations.ai image routes (premium, they fail with "insufficient pollen")
   - On HTTP 429: waits 20 seconds and retries, up to 5 times
3. Add rule 9 to the IMAGE RULES:
   9. BACKUP ENGINE: only if Codex hits its usage limit or fails, use Pollinations. Every Pollinations image must be polished automatically after saving: upscale 1.6x with Lanczos, apply UnsharpMask(radius=2, percent=120, threshold=2), then apply the normal compression rule.
4. Test with one image and show me the result.

Backup option B — Leonardo.ai (manual, high quality)

  • Free tier: 150 tokens/day (≈ 30–50 images) — much better quality than the free Pollinations lane
  • Generate in the browser → download → drop the file into your book's images/ folder → tell Claude Code: "embed this image under the section about X"

🛠️Troubleshooting table — every error we met & its fix

Error / symptomWhat it meansFix
"Permission denied by Claude Code auto mode classifier… danger-full-access" Codex was launched with the unsafe "remove all safety locks" switch, and the security guard blocked it. Step 1 of this guide. Never authorize danger-full-access — workspace-write does the job safely.
"read-only workspace prevented saving" — but Codex says the image was generated The image IS on your disk, in C:\Users\You\.codex\generated_images\… — a known Windows sandbox quirk blocked the final save. IMAGE RULES 3–4 (the delivery step). Claude Code copies the PNG from that folder, renames it, and compresses it. Nothing is ever lost.
Claude Code falls back to HuggingFace, then quota errors HuggingFace MCP tools have tiny quotas. IMAGE RULE 1 bans HuggingFace permanently.
Codex settings seem ignored after editing config.toml Usually duplicates (same setting twice) or backslashes in paths. One copy of each setting; forward slashes C:/… only; save and restart Claude Code.
Images from free tools look blurry Free tiers often serve weaker models (check with your eyes: soft edges = weak model). Use Codex as primary. Apply the upscale + sharpen polish to backup images.
"429 RESOURCE_EXHAUSTED… limit: 0" from an image API The provider has removed free image access via API (this happened with Google Gemini in 2026). Don't fight it — that route needs billing. Use Codex + backups instead.
Files huge, book folder bloated Raw PNGs are often 5+ MB each. IMAGE RULE 7 auto-compresses: max 1600px, JPEG quality 85, under 500 KB.

🔐Golden security rules

  • 🔑 API keys are like ATM PINs. Store them only in the .env file — never in CLAUDE.md, never in chat logs you share, never committed to git (add .env to .gitignore).
  • 👁️ Secret keys (like sk_…) are shown only once at creation — copy immediately.
  • ♻️ If a key ever leaks: delete/regenerate it at the provider's dashboard. It takes 30 seconds.
  • 🚫 Never run Codex with danger-full-access just to "make things work" — that switch disarms ALL safety locks on your PC.
