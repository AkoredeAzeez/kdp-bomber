# AIRF 2.0 Activity Edition — Production phases (ordered)​‍‍​‌‍‌‌‍‍‌‌‍‌‌‌‍‍‍‍‍‌‍‍‍‌‍‌‌‌‌‍‌‌‍‌​

Authoritative narrative: `../../SKILL.md` (Phase 0, Book Architecture, Content Rules, QA Checklist).
This is the ordered execution contract both agents follow; each phase ends at the named gate.

1. **Phase 0 — Title analysis & auto-configuration.** Title clearance (trademark + claims scan);
   subject analysis — lock the dominant activity family (+ up to three supporting families),
   record the mandatory Language-Independence Classification per item, lock the audience band;
   generate 3–5 subtitle candidates (every number becomes a locked count promise); auto-configure
   (100-page default, trim, ink, single-sided budget, difficulty policy, answer policy); build the
   count-reconciliation ledger; assign project_id/edition_id; write the risk register; freeze the
   contract. → **Gate 1 (Contract & Architecture)**
2. **Phase 1 — Manifest build.** Every answer-bearing activity gets a manifest row from structured
   source data (word bank → grid → placements → answers; maze topology → route → uniqueness;
   number/logic constraints → givens → solution → uniqueness; visual object/difference ledger;
   trivia claim → source+date → answer; dot-to-dot coordinate sequence). No puzzle exists on a page
   before it exists in the manifest.
3. **Phase 2 — Representative sample (when required).** 10-page sample: premise/promise, how-to-use,
   legend/worked example, ≥4 substantive activities prototyping the hardest mechanics, capstone,
   solutions. Lock the visual specification and image acceptance criteria. → **Gate 2 (Manifest & Sample)**
4. **Phase 3 — Full content generation & validation.** Generate all activities from the manifest;
   render the three-layer page model (art / overlay text / answer-bearing marks). Run the full
   solvability audit (uniqueness where promised), duplicate-puzzle scan, difficulty-arc test-solve,
   diversity-quota check, accidental-offensive-string scan, and independent test-solve from the
   rendered page. → **Gate 3 (Full Content Validation)**
5. **Phase 4 — Solutions section.** Every answer-bearing item at the back, keyed by item ID and
   final page number; visual answers annotated (circled objects, drawn maze route); reasoning for
   deduction/riddle/trivia.
6. **Phase 5 — Layout, pagination & synchronization.** Paginate; run the post-pagination sync audit
   (item ID ↔ final page ↔ answer ↔ visual asset ↔ locale); confirm gutter/safe zones and blank-back
   positions.
7. **Phase 6 — Preflight & release.** Confirm exact page count and promised activity count on the
   final PDF; 300 ppi imagery; embedded fonts; B&W fidelity; cover wrap after interior lock;
   metadata claim reconciliation; AI-content disclosure; live KDP previewer. → **Gate 4 (Layout,
   Solutions Sync & Preflight)**

Atomic production/resume unit = one manifest-backed Puzzle Unit (or one named front/back-matter section
or one solutions batch). Production resumes at `next_unfinished_item`; it never re-runs Phase 0
(title classification, family, language-independence class, audience band, and count ledger are
locked). One language-market edition = one edition_id with language-dependent puzzles rebuilt from
the locale word bank, never mechanically translated.
