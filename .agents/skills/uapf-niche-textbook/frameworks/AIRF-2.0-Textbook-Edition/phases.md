# AIRF 2.0 Textbook Edition — Production phases (ordered)​‍‍​‌‍‌‌‍‍‌‌‍‌‌‌‍‍‍‍‍‌‍‍‍‌‍‌‌‌‌‍‌‌‍‌​

Authoritative narrative: `../../SKILL.md` (Phase 0, Book Architecture, QA Checklist). This is the
ordered execution contract both agents follow; each phase ends at its named gate. OV-TEXT is also
the DEFAULT TEMPLATE: a title with no dedicated overlay runs this contract, mapped to the nearest
of the nine domains.

0. **Phase 0 — Title analysis & auto-configuration.**
   0.1 Title Clearance Gate (language lock, marketplace, live collision + trademark search across
       Nice classes 16/9/41, clearance rating CLEAR/CAUTION/HIGH RISK/UNVERIFIED, Title Clearance
       Report). 0.2 Subject analysis & Discipline Adaptation Engine domain detection (one of nine;
       Engineering activates the Engineering Domain Directive). 0.3 Subtitle generation (6-8 options,
       combined title+subtitle under 200 chars). 0.4 Auto-configuration (audience, visual level,
       reference approach, assessment architecture, supplementary materials, two-color pairing
       collision-checked, structural signature, pen name). 0.5 TOC lock with per-chapter image plan
       and page targets. Stamp the canonical line into `book_lock.md` with
       `framework=AIRF 2.0 Textbook Edition`. → **Gate 1 (Post-Phase 0)**
1. **Front matter.** Title page; copyright page with discipline-adapted educational/liability
   disclaimer; linked TOC; List of Figures/Tables and Abbreviations (recommended); Preface / How to
   Use This Book (begins arabic page 1). Front matter in lowercase roman numerals.
2. **Chapters (repeat per chapter, in TOC order).** Each chapter built from the Chapter Formula:
   opener (500-750 words) → Learning Objectives box (3-5 Bloom-aligned, measurable, assessment-traced)
   → 3-5 numbered X.Y sections in the locked flow with worked examples → feature boxes (3-5 custom
   devices) → visuals at fixed teaching points → assessment block (omitted in Engineering, replaced
   by extended technical exposition; Engineering also requires one realistic photographic image per
   subchapter and 23+ pages) → close (500-750 words) with narrative bridge. Chapter appended once to
   the cumulative manuscript, never regenerated. → **Gate 2 (Per-Chapter), every chapter**
3. **Back matter.** Appendices (formulas, symbols, standards/data tables, code, timelines);
   complete worked answer key covering 100% of assessment items (omitted only in Engineering);
   discipline glossary; verified references in one consistent style; index; About the Author
   (no fabricated credentials).
4. **Manuscript-complete audit.** Front/back-matter completeness, numbering, disclaimer, answer-key
   coverage, Citations-to-Verify ledger resolved, objective-to-assessment trace, structural
   conformance, total-page band, strict two-color hold. → **Gate 3 (Manuscript Complete)**
5. **Release.** PDF/eBook preflight, metadata match (under 200 chars), AI-disclosure and rights,
   high-risk domain read, catalog log update. → **Gate 4 (Release)**

Atomic production/resume unit = one chapter (Phase 2) or one named front/back-matter section. the production agent
resumes at `next_unfinished_item`; it never re-runs Phase 0 (title clearance, domain detection,
subtitle, configuration, color pairing, structural signature, pen name, and TOC are locked).
