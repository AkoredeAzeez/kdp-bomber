# AIRF 2.0 User Guide Edition — Production phases (ordered)​‍‍​‌‍‌‌‍‍‌‌‍‌‌‌‍‍‍‍‍‌‍‍‍‌‍‌‌‌‌‍‌‌‍‌​

Authoritative narrative: `../../SKILL.md` (Phase 0, Book Architecture, QA Checklist). This is the
ordered execution contract both agents follow; each phase ends at the named gate. The standalone
gate phrase for OV-GUIDE is **"Type Proceed."** (configuration gate: "Shall I proceed with the
Table of Contents? Type Proceed to continue.")

1. **Phase 0 — Title analysis & auto-configuration.** Trademark clearance FIRST (nominative fair
   use; CLEAR/CAUTION/BLOCKED); product & version identification (the most critical step — version
   named on cover, Introduction, metadata); product architecture analysis (terminology master
   list); task analysis & chapter scope (task-oriented, never feature-organized); audience
   definition; competitor version analysis; 7 subtitle candidates; auto-config (pathway, page band,
   visual density, font, spacing, screenshot convention, Design Signature). Stamp the canonical
   classification line into `book_lock.md` with `framework=AIRF 2.0 User Guide Edition`.
   → **Gate 1 (Pre-Creation Foundation)**
2. **Front matter (mandatory order).** Title Page (with version parenthetical); Copyright Page
   (version + no-affiliation + trademark + variance disclaimer); live Word TOC; Preface (1 p);
   How to Use This Book (1 p); Introduction (visible pagination starts at page 1, names version +
   cutoff, Before You Begin checklist).
3. **Getting Started + Product Overview.** Chapter 1/2 — setup, account, first-launch walkthrough
   enabling first-use success in one session; interface tour, navigation map, key terminology.
4. **Core task chapters (repeat per chapter).** Task-oriented title; Before You Begin prerequisites;
   numbered procedures (one action per step, bold UI element names matching the product exactly);
   annotated screenshots/diagrams with callout tables; ANSI warning hierarchy at the step of risk;
   Version Notes on any prior-version difference; Common Issues; Chapter Checkpoint. Each chapter
   passes the terminology-parity + technical-accuracy audit. → **Gate 2 (per chapter)** then
   **Gate 3 (per-chapter terminology parity)**
5. **Settings & Customization, Maintenance & Updates, Troubleshooting.** Closing task chapters;
   Troubleshooting addresses the top 10 documented user problems.
6. **Conclusion.** Exactly 1.5 pages; capabilities summary; staying-current guidance; community
   resources; no new procedures.
7. **Appendix (all seven elements).** Quick Reference Card; Keyboard Shortcuts Reference;
   Troubleshooting Index; Glossary; Interface Element Naming Index; Version History Note; Resource
   Directory.
8. **Release / Final Certification.** Version named on all four touchpoints; front matter order and
   page shapes; terminology parity cross-referenced against the Interface Element Naming Index;
   warning-hierarchy compliance; anti-AI language sweep; Design Signature logged; one rolling
   master DOCX with live TOC. → **Gate 4 (Final Certification)**

Atomic production/resume unit = one task chapter (Phases 4-5) or one named front/back-matter section.
Production resumes at `next_unfinished_item`; it never re-runs Phase 0 (trademark verdict, covered
version, product architecture, task-to-chapter map, and configuration are locked in `book_lock.md`).
